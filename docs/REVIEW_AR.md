# المراجعة والتصحيح وسجل التدقيق

> **الحالة:** منفّذ ومختبَر على بيانات اصطناعية. هذا جزء من المرحلة 3 في الخطة، وبُني مبكرًا لأنه لا يحتاج عينات.

## ما تفعله الشاشة

| الإجراء | ما يحدث |
|---|---|
| **عرض الأسئلة** | قوائم حسب الحالة مع أعدادها: تحتاج مراجعة، بانتظار الاعتماد، معلّمة للجنة، معتمدة، الكل. الأقل ثقة يظهر أولًا |
| **تعيين الإجابة** | الضغط على خيار. يُحفظ في `CorrectedIndex` منفصلًا، و**`OriginalCorrectIndex` لا يتغير أبدًا** |
| **إلغاء التصحيح** | تعود إجابة الملف. واختيار إجابة الملف نفسها يعني «لا تصحيح» |
| **الاعتماد** | يُرفض إذا لم تكن هناك إجابة. السؤال المعتمد لا تُعدَّل إجابته إلا بعد «إعادة الفتح» |
| **التعليم للجنة** | يضع السؤال في قائمة «معلّمة للجنة» |
| **إعادة الفتح** | يعيد السؤال إلى «بانتظار الاعتماد» أو «تحتاج مراجعة» حسب ثقته |
| **التراجع** | كل عملية لها زر «تراجع» لمدة 5 ثوانٍ |
| **لوحة المفاتيح** | `J` و`K` للتنقل، `A` للاعتماد، `F` للتعليم للجنة |

يظهر بجانب الخيار الأصلي وسم «الإجابة في الملف» عندما يختلف عنه التصحيح، وتظهر ملاحظة باسم من صحّح.

## سجل التدقيق

جدول `AuditLog`، يُكتب **في المعاملة نفسها** مع التغيير، فلا يوجد تغيير بلا سجل:

| الحقل | مثال |
|---|---|
| `User` | `CORP\reviewer` |
| `Action` | `SetAnswer` أو `RevertAnswer` أو `Approve` أو `Flag` أو `Reopen` أو `Supersede` |
| `EntityType` و`EntityId` | `Question` و`4` |
| `OldValue` و`NewValue` | `NeedsReview` ثم `Approved`، أو رقم الخيار قبل وبعد |

**لا يحتوي نص أي سؤال.** السجل يشير إلى السؤال برقمه فقط. تكرار العملية نفسها (مثل اعتماد سؤال معتمد) لا يُنشئ سجلًا جديدًا.

## حماية عمل المراجعين عند تغيّر الملفات

| الحالة | ما يحدث |
|---|---|
| إعادة استخراج **المحتوى نفسه** | لا شيء يتغير، فالتصحيحات والاعتماد تبقى |
| **تغيّر الملف** | الأسئلة غير المراجَعة تُحذف وتُستبدل. **الأسئلة المراجَعة لا تُحذف**: تصبح «مُستبدَلة» (`Superseded`) مع سجل `Supersede` باسم `system`، وتبقى للتتبع، ولن تُصدَّر |
| عودة الملف إلى محتوى قديم | تُستخرج أسئلة جديدة بمعرّفات مميّزة، فلا تصطدم بالأسئلة المستبدَلة المحفوظة |

## نقاط API

| الطريقة | المسار | الوظيفة |
|---|---|---|
| GET | `/api/review?status=&skip=&take=` | قائمة الأسئلة مع أعداد كل حالة |
| GET | `/api/review/{id}/history` | سجل التدقيق للسؤال |
| POST | `/api/review/{id}/answer` | `{"index": 2}` لتعيين الإجابة، أو `{"index": null}` لإلغاء التصحيح |
| POST | `/api/review/{id}/approve` | اعتماد |
| POST | `/api/review/{id}/flag` | تعليم للجنة |
| POST | `/api/review/{id}/reopen` | إعادة فتح |

الصلاحية لمدير النظام ومسؤول البنك والمراجع الفني. مستخدم الاطلاع ممنوع. كل طلب تغيير يحتاج ترويسة `X-QB-Client` (حماية CSRF).

## الاختبارات

**126 اختبارًا، جميعها ناجحة**، منها 15 جديدة:
- الترتيب حسب الثقة.
- طبقة التصحيح لا تغيّر الأصل.
- السجل يُكتب بلا نصوص.
- إلغاء التصحيح.
- رفض رقم خيار خاطئ.
- الاعتماد يحتاج إجابة.
- المعتمد مقفل حتى إعادة الفتح.
- لا تكرار في السجل.
- إعادة الاستخراج تحفظ المراجعة.
- تغيّر الملف يحوّل المراجَع إلى «مُستبدَل».
- عودة المحتوى القديم لا تصطدم بالمعرّفات.
- الصلاحيات وحماية CSRF.

**تجربة فعلية في المتصفح:**
1. محاولة اعتماد سؤال بلا إجابة: رُفضت برسالة واضحة.
2. تعيين الإجابة بالضغط على خيار.
3. الاعتماد بلوحة المفاتيح.
4. اعتماد سؤال من قائمة «بانتظار الاعتماد».

قاعدة البيانات أظهرت التصحيح منفصلًا عن الأصل، وثلاثة سجلات تدقيق صحيحة.

## لم يُنجز بعد
- مراجعة ثنائية (مراجعان للأسئلة منخفضة الثقة).
- توزيع الأسئلة على المراجعين.
- تصحيح النص نفسه أو دمج سؤالين أو فصلهما. حاليًا التصحيح للإجابة فقط.
