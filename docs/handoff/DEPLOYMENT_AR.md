# تعليمات النشر الآمن — Windows Server

## 1) قبل النشر
- نسّق مع مسؤول تقنية المعلومات للحصول على اسم الخادم، اسم DNS داخلي، شهادة TLS داخلية، ومنافذ مسموحة.
- تحقق هل SQL Server موجود، وما النسخة وسياسة النسخ الاحتياطي. لا تفترض وجوده.
- حدد مشاركة SMB المصدر ومجلد النتائج؛ يجب ألا يكونا المسار نفسه.
- اختبر على بيانات غير سرية أولًا.

## 2) حساب الخدمة والصلاحيات
- أنشئ حساب خدمة مخصصًا وفق سياسة المؤسسة (يفضّل gMSA إن كان مدعومًا ومناسبًا).
- امنح الحساب Read/List فقط على مجلد المصدر.
- امنحه Modify فقط على مجلد النتائج والسجلات.
- لا تمنحه Local Administrator ولا صلاحيات حذف المصدر.
- لا تستخدم حساب الموظف الشخصي أو قرصًا شبكيًا مربوطًا بجلسة تفاعلية.
- تأكد من صلاحيات المشاركة وصلاحيات NTFS معًا؛ كلاهما مؤثر.

## 3) إعداد التطبيق
- ثبّت .NET 8 Hosting Bundle من مصدر Microsoft الرسمي المعتمد لدى المؤسسة.
- انشر التطبيق في مجلد مثل `C:\Apps\QuestionBank\Web`.
- احتفظ بالإعدادات السرية خارج مجلد النشر أو ضمن آلية الأسرار المعتمدة.
- اضبط `QuestionBank__SourceRoot` على مسار UNC مثل `\\FILESERVER\QuestionBankReadOnly`.
- اضبط `QuestionBank__OutputRoot` على مجلد منفصل مثل `\\FILESERVER\QuestionBankOutput`.
- لا تخزّن بيانات اعتماد الشبكة في `appsettings.json`.

## 4) IIS والشبكة
- أنشئ موقع IIS داخليًا للتطبيق، واجعل Application Pool يستخدم هوية الخدمة المعتمدة.
- فعّل HTTPS بشهادة داخلية موثوقة.
- اسمح بالوصول من شبكات/أجهزة المؤسسة المطلوبة فقط عبر جدار الحماية.
- لا تنشر المنفذ مباشرة إلى الإنترنت ولا تستخدم Port Forwarding.
- أوقف صفحات الأخطاء التفصيلية في بيئة الإنتاج، ولا تعرض stack traces للمستخدمين.

## 5) قاعدة البيانات
- إذا كان SQL Server متوفرًا، اطلب من مسؤول قواعد البيانات إنشاء قاعدة مخصصة وحساب محدود الصلاحيات.
- لا تستخدم حساب `sa` في التطبيق.
- استخدم حسابًا بصلاحيات محدودة على قاعدة المشروع، مع نسخ احتياطي واستعادة مجرّبة.
- لا تنفذ `schema.sql` على خادم إنتاج دون مراجعة DBA وخطة تغيير معتمدة.

## 6) التشغيل التجريبي
- ابدأ بمجلد تجريبي صغير.
- تحقق من أن التطبيق يستطيع تعداد الملفات وقراءة البيانات التجريبية فقط.
- اختبر إيقاف الخدمة وإعادة تشغيلها، وانقطاع الشبكة، والملفات المقفلة، والمسارات غير المتاحة.
- قارن عدد الملفات المرصودة مع عدد الملفات المتوقع يدويًا.
- لا تبدأ المعالجة الكاملة قبل اختبار الأداء والنسخ الاحتياطي والصلاحيات.

## 7) المراقبة والتدقيق
- سجل معرف الملف، وقت المعالجة، الحالة، عدد المحاولات، ونوع الخطأ؛ تجنب تسجيل نص السؤال أو محتواه في السجلات العامة.
- راقب مساحة القرص، حجم قاعدة البيانات، معدل أخطاء SMB، ومدة الدفعات.
- ضع سياسة احتفاظ للسجلات ونسخ احتياطي حسب سياسة المؤسسة.
