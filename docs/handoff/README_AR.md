# مشروع بنك الأسئلة الداخلي — نسخة تأسيسية

هذه نسخة تأسيسية (Starter) وليست نظامًا إنتاجيًا مكتملًا. هدفها تثبيت الهيكل الآمن واختبار الوصول إلى مجلد الشبكة قبل تشغيل أي استخراج أو تصنيف.

## ما الذي تتضمنه؟
- تطبيق ASP.NET Core Web API على .NET 8.
- فحص صحة التطبيق.
- إعداد مسار المصدر ومجلد النتائج من الإعدادات.
- نقطة API تعرض إعدادات المسارات دون كشف كلمات مرور أو تفاصيل حساسة.
- خدمة خلفية تأسيسية يمكن توسيعها لمعالجة الملفات على دفعات.
- مخطط SQL أولي لتسجيل الملفات والمهام والأسئلة والمطابقات.
- تعليمات نشر داخل الشبكة.

## مهم قبل الاستخدام
1. لا توصل النسخة الأولية ببنك الأسئلة الحقيقي قبل موافقة تقنية المعلومات.
2. ابدأ بمجلد تجريبي يحتوي ملفات غير سرية.
3. لا تفعّل استخراج المحتوى أو المطابقة الآلية قبل اختبار قارئات الملفات ومراجعة سياسة السرية.
4. لا تمنح التطبيق صلاحية حذف أو تعديل المصدر. استخدم حساب خدمة يملك القراءة فقط للمصدر والكتابة فقط إلى مجلد النتائج.
5. لا تفتح المنفذ على الإنترنت؛ اجعل الوصول عبر شبكة المؤسسة أو VPN مؤسسي مصرح به.
6. SQL Server غير مفترض أنه مثبت. تحقق مع مسؤول الخادم أولًا. مخطط `database/schema.sql` يوضح تصميمًا أوليًا فقط، ولا ينشئ قاعدة البيانات أو الصلاحيات تلقائيًا.

## المتطلبات
- Windows Server مدعوم ومحدّث.
- .NET 8 Hosting Bundle (إذا كان النشر خلف IIS).
- مجلد مشترك SMB يمكن لحساب خدمة التطبيق قراءته.
- مسار مستقل للنتائج والسجلات.
- SQL Server عند اعتماد قاعدة البيانات الإنتاجية.

## تشغيل التطوير
من مجلد `src/QuestionBank.Web`:
```powershell
dotnet restore
dotnet run
```
ثم افتح عنوان localhost الذي يظهر في الطرفية، وأضف `/health` أو `/api/config/paths`.

## إعداد المسارات
عدّل `appsettings.json` أو استخدم متغيرات البيئة في بيئة النشر:
- `QuestionBank__SourceRoot`
- `QuestionBank__OutputRoot`
- `QuestionBank__BatchSize`

استخدم UNC مثل `\\FILESERVER\QuestionBankReadOnly` بدل قرص شبكي مربوط بحساب مستخدم. لا تضع كلمات مرور داخل ملفات الإعدادات أو مستودع الكود.

## النشر على Windows Server
راجع `docs/DEPLOYMENT_AR.md` قبل النشر. الخيار المقترح: IIS لواجهة الويب، وحساب خدمة مخصص له صلاحية قراءة المصدر فقط. عند تشغيل Worker منفصل لاحقًا، يُشغّل كـ Windows Service مستقل بنفس مبدأ أقل الصلاحيات.

## مراحل التطوير التالية
1. جرد ملفات آمن وقابل للاستئناف مع سجل لكل ملف.
2. قارئات مستقلة لـ XLSX/DOCX/TXT/MD/GIFT/PDF مع اختبارات عينات.
3. قاعدة بيانات SQL Server ومخطط ترحيلات.
4. واجهة مراجعة للأسئلة والتصنيف.
5. مطابقة الأطر المعتمدة مع حفظ الاسم والرمز حرفيًا، ودرجة المطابقة وحالة المراجعة.
6. فحص التكرار والتداخل دون حذف تلقائي.
7. تصدير Excel وGIFT مع اختبارات تحقق واستيراد تجريبي إلى Moodle.
