# ملف تسليم مشروع بنك الأسئلة إلى Claude

## 1. فكرة المشروع
بناء تطبيق ويب داخلي متعدد المستخدمين لمعالجة بنك أسئلة مؤسسي موجود على مجلد شبكة داخل المؤسسة. حجم العمل التقريبي 24.7 GB، ويضم نحو 78,554 ملفًا و23,173 مجلدًا. سيعمل التطبيق على خادم مخصص بنظام Windows Server، ويُستخدم من عدة أجهزة عبر المتصفح، ولا يحتاج الموظفون إلى تثبيت البرنامج على أجهزتهم.

## 2. الهدف
فهرسة الملفات ومعالجة محتواها تدريجيًا، واستخراج الأسئلة، وربطها بأطر الكفايات الوظيفية المعتمدة، وفحص الجودة والتكرار والتغطية، ثم إصدار تقارير Excel وملفات GIFT صالحة للاختبار والاستيراد في Moodle.

## 3. قيود إلزامية لا يجوز خرقها
1. السرية: البيانات تبقى داخل شبكة المؤسسة. لا ترسل الملفات أو نصوص الأسئلة أو الأطر إلى أي خدمة خارجية أو API سحابي دون موافقة صريحة من المؤسسة.
2. عدم تعديل المصدر: لا تعدّل أو تحذف أو تعِد تسمية ملفات المصدر. حساب الخدمة لديه قراءة فقط على المصدر.
3. المرجع التصنيفي: أطر الكفايات الوظيفية المعتمدة التي توفرها المؤسسة هي المرجع الوحيد لتصنيف الأسئلة. لا تخترع مجالات أو مؤشرات، ولا تعِد تسمية المجالات أو المؤشرات أو الرموز.
4. المحافظة على البيانات: احتفظ بنص السؤال، ورمزه، وترتيبه، وترتيب الخيارات، والإجابة الصحيحة، وبيانات المصدر. لا تغيّر الإجابات ولا تعيد صياغة الأسئلة تلقائيًا.
5. التصنيف: كل سؤال يُربط بأقرب مؤشر موجود فعلًا في الإطار المناسب، مع تسجيل درجة المطابقة، وحالة المطابقة، ومبرر موجز وأدلة داعمة. الحالات غير المؤكدة تُحال للمراجعة البشرية.
6. الجودة: افصل بين التكرار الحرفي، وشبه التكرار، والتداخل المفاهيمي، ونقص التغطية. لا تحذف الأسئلة المكررة تلقائيًا.
7. الاستئناف: المعالجة على دفعات، وتتحمل توقف الخدمة أو انقطاع الشبكة، وتستأنف من قاعدة البيانات دون فقد التقدم أو مضاعفة النتائج.
8. التتبع: كل سؤال يجب أن يحتفظ بمعرّف ثابت ومصدره ومساره ووقت الاستخراج وإصدار الإطار الذي تمت المطابقة عليه.
9. GIFT: حافظ على صياغة GIFT الصحيحة وUTF-8 وترتيب الخيارات والإجابة الصحيحة. لا تصدر سؤالًا لم يتم التحقق من بنيته دون وضعه في تقرير أخطاء.
10. لا تُظهر نصوص الأسئلة أو أسرار الإعدادات في سجلات النظام.

## 4. البيئة
- الاستضافة: خادم مخصص Windows Server داخل شبكة المؤسسة.
- الاستخدام: عدة مستخدمين من متصفحاتهم.
- الملفات: مشاركة شبكة SMB؛ استخدم UNC paths بدل أحرف الأقراص المربوطة بجلسة مستخدم.
- SQL Server: غير معلوم التوفر؛ تحقق قبل اختياره. لا تفترض أنه مثبت.
- التقنية المقترحة: ASP.NET Core / .NET 8 لواجهة API والخدمة الخلفية، SQL Server عند توفره واعتماده، قارئات ملفات متخصصة، وتقارير XLSX وGIFT.
- يمكن استخدام IIS للواجهة وWindows Service مستقلة للعامل الخلفي.
- يلزم HTTPS داخلي، وصلاحيات حسب الدور، وحساب خدمة مخصص بأقل صلاحيات، ومجلد نتائج مستقل.

## 5. أدوار المستخدمين المقترحة
- مدير النظام: إدارة الحسابات والإعدادات والمهام.
- مسؤول بنك الأسئلة: إدارة الاستيراد والفهرسة وتشغيل المعالجة والتقارير.
- المراجع الفني: مراجعة التصنيفات واعتمادها.
- مستخدم الاطلاع: البحث والاطلاع ضمن صلاحياته.

## 6. وحدات النظام
### أ. إدارة المصادر والفهرسة
- تحديد جذر مصدر مسموح به من الإعدادات، وليس من مسار حر يدخله المستخدم.
- تعداد تدريجي للملفات.
- تسجيل المسار النسبي والامتداد والحجم وتاريخ التعديل وبصمة المحتوى عند الحاجة.
- حالات الملف: Pending, Processing, Completed, Failed, Skipped, NeedsReview.
- إعادة المحاولة مع حد أقصى وتأخير متدرج.
- كشف تغيّر الملف وإعادة معالجته عند تغيره فقط.
- عدم متابعة الروابط الرمزية أو المسارات التي تخرج عن جذر المصدر.

### ب. استخراج الأسئلة
ابدأ بالامتدادات الأكثر شيوعًا في عينة فعلية. الامتدادات المحتملة: XLSX, XLS, DOCX, DOC, TXT, MD, GIFT, PDF. لا تفترض دعم كل صيغة قبل بناء واختبار قارئ لها. ملفات PDF المصورة قد تحتاج OCR محليًا، ويجب أن تكون هذه الوظيفة اختيارية ومختبرة.

### ج. أطر الكفايات
- استيراد الأطر من ملفات المؤسسة.
- تخزين اسم الإطار وإصداره ومسار المصدر.
- حفظ أسماء المجالات الرئيسية والفرعية ورموز المؤشرات حرفيًا.
- لا تستخدم اسم الملف وحده لتعيين المؤشر إذا لم يكن هناك دليل كافٍ.
- لا تدمج أطر تخصصات مختلفة دون قاعدة معتمدة.

### د. المطابقة
- إنشاء مرشحين للمؤشر ثم ترتيبهم.
- تسجيل score وحالة واضحة مثل: Matched, NeedsReview, Unmatched.
- درجة المطابقة ليست وحدها دليلًا على الصحة؛ يجب حفظ مبرر أو دليل.
- اعتماد الإنسان مطلوب للحالات منخفضة الثقة أو المتعارضة.
- يجب أن تكون حدود الثقة قابلة للضبط والاختبار على عينة راجعها مختصون.

### هـ. فحص الجودة
- تكرار حرفي بالبصمة بعد تطبيع آمن لا يغيّر النص الأصلي.
- شبه تكرار باستخدام مقارنة نصية.
- تداخل مفاهيمي كفئة منفصلة.
- فحص بنية السؤال والخيارات والإجابة الصحيحة.
- عدم حذف أو تعديل أي سؤال تلقائيًا.

### و. التصدير والتقارير
- Excel: جرد الملفات، الأسئلة المستخرجة، نتائج المطابقة، التكرار، التغطية، الأخطاء.
- GIFT: تصدير بعد اختيار التخصص/المجال/المؤشر وحالة الاعتماد؛ UTF-8 والتحقق من الهروب للرموز الخاصة.
- تقارير استثناءات لكل ملف تعذر قراءته.
- الاحتفاظ بنسخة من إعدادات التصدير وسجل عملية التصدير.

## 7. قاعدة البيانات
راجع `database/schema.sql` في هذه الحزمة. هو مخطط أولي وليس ترحيلًا إنتاجيًا مكتملًا. راجعه مع DBA قبل التشغيل. يُتوقع وجود جداول للملفات، وعمليات المعالجة، والأسئلة، وأطر الكفايات، والمؤشرات، والمطابقات، وسجل التدقيق، وتاريخ التصدير.

## 8. ملفات النسخة الأولية الحالية
- `src/QuestionBank.Web/`: هيكل API أولي على ASP.NET Core.
- `appsettings.json`: مسارات تجريبية يجب استبدالها.
- `database/schema.sql`: مخطط SQL أولي.
- `docs/DEPLOYMENT_AR.md`: تعليمات نشر آمن.
- `docs/ROADMAP_AR.md`: خارطة طريق.
- `README_AR.md`: شرح الحزمة.

هذه النسخة لا تنفذ الجرد الكامل أو استخراج الأسئلة أو المطابقة أو تصدير GIFT حتى الآن. لا تصفها بأنها جاهزة للإنتاج.

## 9. خارطة التنفيذ
1. راجع الهيكل الحالي ونفّذ build ناجحًا.
2. أضف مصادقة وصلاحيات قبل إتاحة التطبيق لمستخدمين آخرين. لا تعرض مسارات الخادم في واجهة المستخدم النهائية.
3. صمّم نموذج إعدادات آمنًا لمسار المصدر والنتائج.
4. نفّذ جردًا قابلًا للاستئناف بقاعدة بيانات دائمة. اختبره على عينة غير سرية.
5. أضف لوحة حالة للدفعات والأخطاء.
6. أضف قارئات الملفات على مراحل، كل قارئ مع اختبارات وحدود حجم ووقت.
7. أضف استيراد أطر الكفايات ثم المطابقة مع سجل مراجعة.
8. أضف تقارير الجودة والتكرار والتغطية.
9. أضف تصدير XLSX وGIFT مع اختبارات آلية.
10. اختبر الصلاحيات، واستعادة الخدمة، وفقدان اتصال SMB، والملفات المقفلة، والنسخ الاحتياطي، والأداء قبل معالجة المجلد الكامل.

## 10. معايير القبول
- لا تتغير أي ملفات مصدر خلال الاختبارات.
- يمكن إيقاف العامل وإعادة تشغيله دون فقدان تقدم أو تكرار النتائج.
- كل ملف يظهر بحالة مفهومة.
- كل سؤال مستخرج يحتفظ بمصدره ورمزه وترتيبه والإجابة الأصلية.
- لا توجد مؤشرات تصنيف غير موجودة في إطار معتمد.
- الحالات غير المؤكدة تظهر للمراجع.
- ملفات GIFT الناتجة تمر باختبارات الصياغة وتُجرّب على Moodle تجريبي.
- لا يحدث اتصال خارجي من مكونات المعالجة دون موافقة.
- توجد تعليمات تشغيل واستعادة ونسخ احتياطي موثقة.

## 11. المطلوب من Claude الآن
1. افحص ملفات المشروع الأولية الموجودة في الحزمة.
2. اشرح أي أخطاء أو نواقص في الهيكل الحالي قبل التوسع.
3. أنشئ خطة تنفيذ قصيرة على شكل مراحل وملفات محددة.
4. ابدأ بالمرحلة الأولى فقط: بناء جرد آمن وقابل للاستئناف، مع اختبارات وحدة وتوثيق.
5. لا تبنِ كل شيء دفعة واحدة، ولا تفترض وجود SQL Server.
6. لا تستخدم خدمات خارجية أو بيانات بنك أسئلة حقيقية.
7. قدم تغييرات صغيرة قابلة للمراجعة، مع قائمة بالملفات التي تغيرت وأوامر البناء والاختبار.
